## アーキテクチャ

```
+--------------------------------------------------+
| Electron アプリ                                   |
|                                                  |
|  メインプロセス (Node.js)                          |
|   - 気象データのダウンロード (NOMADS / CDS)        |
|   - GRIB2 → JSON 変換 (将来: wgrib2 同梱)         |
|   - ローカルキャッシュ (userData ディレクトリ)      |
|   - IPC でレンダラーにデータ提供                    |
|                                                  |
|  レンダラープロセス (Three.js / WebGL)             |
|   - 地球儀 (SphereGeometry + テクスチャ)           |
|   - 風パーティクルの移流と流線描画                  |
|   - カメラ操作 (OrbitControls)                    |
|   - UI (日時選択、高度選択、表示設定)               |
+--------------------------------------------------+
```

- セキュリティ方針: `contextIsolation: true` / `nodeIntegration: false` とし、
  レンダラーからのデータ取得は preload 経由の IPC に限定する。
- ビルド: レンダラーは Vite でバンドル、メインプロセスと preload は esbuild でバンドルする。
  開発サーバーは使わず、`npm run build` → `npm start` のシンプルな構成から始める。

## 風データの形式

cambecc/earth (nullschool のオープンソース版) と同じ GFS JSON 形式を内部形式として採用する。

- U 成分(東西風)と V 成分(南北風)の 2 レコードからなる配列。
- 各レコードは `header` (nx, ny, lo1, la1, dx, dy など格子情報) と `data` (行優先の値配列) を持つ。
- 格子は緯度経度の等間隔格子(プロトタイプは 1.0°、将来は 0.25°)。
- 北端 (la1=90) から南へ、西端 (lo1=0) から東へ走査する。

この形式なら grib2json (nullschool 作者の変換ツール) の出力をそのまま読める。

### P3: 描画の高度化

- [x] GPU パーティクル化(2026-06-13 完了)
  - 粒子状態 (lon, lat, age, maxAge) を RGBA32F テクスチャに持ち、ping-pong FBO で移流
  - 風場は半精度テクスチャに焼き、補間は GPU のバイリニアフィルタに任せる
  - 軌跡は画面スペースの蓄積バッファ(減衰コピー + 点描)。蓄積バッファ内で
    地球を深度のみ描画して裏側の粒子を隠す
  - 粒子数は 16,384〜1,048,576 から選択(既定 262,144)、262k で 120fps
  - カメラ操作中は減衰を強めてスミアを抑制
  - 浮動小数点レンダーターゲット非対応環境では従来の CPU 移流(6000 粒子)に
    フォールバック(`particles.ts` は残す)
- [x] ベクター海岸線 + LOD(2026-06-13 完了)
  - 海岸線をテクスチャ描画からベクターライン (LineSegments) に変更し、ズームしても
    輪郭が常にシャープに保たれるようにした
  - カメラ距離で Natural Earth 110m / 50m / 10m を自動切替。10m (約19MB) は
    初回ズーム時に動的 import で遅延ロード
  - 長い線分は弦の沈み込みを防ぐため 1.5° 以下に分割
  - 陸地の塗りも 50m データ + 4096×2048 キャンバスに更新
- [x] 風速のカラーオーバーレイ(地表の色塗り)— 2026-06-13 完了
  - 風場テクスチャをフラグメントシェーダーで直接サンプリングする半透明球を重ねる
    (`overlay.ts`)。チェックボックスで ON/OFF、濃度スライダーと凡例付き
- [ ] 等圧面(850hPa / 500hPa / 250hPa など)の高度切り替え
- [ ] 0.25° 格子への対応
- [ ] 背景の星を実際の星カタログにする(2026-06-13 追加)
  - 現状はランダムな点。HYG データベース等から赤経・赤緯と等級を取得し、
    天球上に正しい相対配置で描く(星座の形が分かるレベルを目標)
  - 等級で点の大きさ・明るさを変える。B-V 色指数による色付けも検討
  - 地球の自転との厳密な時刻同期まではしない

### P5: 風データDB・時間アニメーション(完了 2026-06-13)

取得した風を使い捨てにせず貯め、一定区間を連続再生できるようにした。

- [x] ファイル型ストア(`src/main/store.ts`)
  - 保存先は `userData/wind-db/<id>/`(パッケージ化しても書き込める場所)
  - `meta.json` に名前 / 出自 / 格子情報 / 各フレームの有効時刻を持つ
  - 各フレームは `frame-XXXX.bin`(u[nx*ny] + v[nx*ny] を Float32 LE で連結、
    1°格子で約0.5MB/枚)。格子情報は全フレーム共通なので meta に1回だけ持つ
  - 一覧はサブディレクトリの meta.json 走査で作り、別途の索引は持たない
- [x] 区間ビルド(`src/main/db-build.ts`)
  - 予報: `fetchGfsWind` を開始〜終了予報時刻まで指定刻みでループ
  - アーカイブ: 開始〜終了日時を指定刻み(既定3h)で `fetchArchiveWind` をループ
  - 逐次取得・途中失敗はスキップして続行・進捗を `db:build-progress` で逐次通知
  - 暴走防止に1コレクション最大240フレーム、丸めで重複する有効時刻はスキップ
- [x] 区間管理UI / 再生UI(`src/renderer` の「保存データ / アニメーション」)
  - 一覧(名前・出自・期間・コマ数、行クリックで読込、× で削除)
  - 新規作成(名前、出自選択、アーカイブ=開始/終了、予報=開始/終了予報時刻、刻み)
  - 再生(再生/一時停止・スクラブ・速度=秒/コマ・開始/終了位置・ループ・フレーム補間)
  - 全フレームをメモリに展開し、既存の `applyWind()` で風だけ差し替えて滑らかに繋ぐ
  - フレーム補間: 再生位置を連続値にし、隣接2コマの u/v を時間補間して風場を滑らかに
    変化させる。GPUパーティクル・オーバーレイはテクスチャをその場更新(`writeWindInterp`)。
    CPUフォールバックでは無効
- [x] `npm run test:db` で保存・読み出し・削除を Electron 上で検証

## リスクと対策

| リスク | 対策 |
|---|---|
| GRIB2 の JS パースが弱い | wgrib2 / grib2json を同梱しメインプロセスから呼ぶ。P0 ではサンプル JSON で回避 |
| CPU パーティクルの性能限界 | P0 は 1 万粒子以下に抑え、P3 で GPU 化 |
| CDS API の登録が必要 | P2 で API キー設定 UI を用意。P0/P1 は GFS のみで成立させる |
| 極付近の移流の歪み | 緯度による経度補正 (1/cosφ) と極近傍での粒子リセットで対処 |
